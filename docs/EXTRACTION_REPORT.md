# Director extraction and browser port

## Canonical input

The port is derived from `spacedpenguin_bigidea_20020806.dcr`, the original Big
Idea web capture. It is 92,896 bytes and has SHA-256
`22d7a9f9455467c277a0ea920cf1042073f7744446aaecb40476f586941df102`.
The reconstructed Director movie is 347,151 bytes with SHA-256
`a655723a84fcc6e575c6da4371fff0aeb0bdee2ba2c40c4d6c0a9a54cfaf99d8`.
Neither vintage executable is run on the host; authoring and runtime queries
execute only in the disconnected cached Windows Sandbox.

## Recovered content

- 21 Lingo scripts plus their ProjectorRays bytecode listings;
- 140 catalogued member records, including registration points and source text;
- 48 original bitmap PNGs and five original WAV samples;
- 18 original vector SWFs, converted deterministically to 18 SVGs while the
  SWFs are retained beside them in generated output;
- all 64 Score frames, 2,108 sprite rows, 74 occupied sprite channels, seven
  frame labels, behavior attachments, ink/blend/rotation/geometry fields, and
  114 referenced members;
- 25 playable levels on Director frames 11–35, plus Intro, Tips, Levels,
  High Score Form, End Stats, and High Score Sending screens.

`pnpm assets:generate` rebuilds the browser input from ignored preservation
artifacts. It also reproduces Director ink-8 edge-connected matte transparency
for Kevin and the ship, converts vector SWFs without redrawing them, and derives
clean menu backgrounds from independent Director Stage captures. Every emitted
asset is hashed in the ignored `public/assets/manifest.json`.

## Port architecture

The deployed result is static `index.html`, CSS, and JavaScript. TypeScript is
used only as a build-time language; there is no UI framework and no runtime
server dependency. The deterministic core advances exactly one Director frame
per `tick`, never reads the browser clock, and drives Canvas 2D and Web Audio as
output adapters. The browser loop is fixed at 30 fps over a 500 by 400 logical
stage.

All authored levels are data-driven from the recovered Score. The compatibility
layer preserves observed Director integer-point arithmetic, sprite location
quantization, handler ordering, collision rectangles, odd-width radii, and the
original bug where a planet-list index is later interpreted as a sprite
channel. Original bitmaps, converted original vectors, text, and WAV samples
are used directly.

## Independent verification

Reference expectations are captured from Director 8 inside Windows Sandbox and
are not generated by the TypeScript implementation. The unit suite checks 294
Director state boundaries:

| Evidence | Samples | Coverage |
| --- | ---: | --- |
| `canonical-api-120` | 121 | launch, flight, target entry, scoring |
| `conformance-level02-bonus-20260830` | 31 | bonus collection, spin-down, reset |
| `conformance-level17-target-orbit-20260830` | 61 | moving target, planets, bonus, crash |
| `conformance-level22-multi-orbit-20260830` | 31 | four bodies and target orbit |
| `all-levels-physics-and-screens-20260830-v2` | 50 | two launch boundaries for all 25 levels |

The Playwright suite drives the public browser testing API and compares the
Canvas with independent 500 by 400 Director captures. Current differences at a
0.1 color threshold are 67 pixels for Intro, 5 for Tips, 2 for End Stats, and 0
for High Score Sending, out of 200,000 pixels per screen. The High Score Form
comparison masks only the explicitly redesigned input region and continues to
compare the authored background around it. The suite also completes the
canonical shot with Director's score of 318 and constructs every level through
the browser API.

## Explicit static-site treatment

The original movie POSTed names, state abbreviations, and scores to an obsolete
unencrypted Big Idea CGI. Production code does not contact it. Finishing level
25 opens the high-score form locally with the approved single Nickname field;
the sending screen and End Stats transition remain, but no personal data leaves
the browser and no global leaderboard is fabricated.

Raw DCR/DIR files, extracted assets, Sandbox runs, screenshots, and generated
web assets remain outside Git as required by the preservation policy. Their
provenance is reproducible through the tracked extraction/generation scripts
and the manifests under `reference/manifests/`.
