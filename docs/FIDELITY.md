# Fidelity strategy

## Goal

The port must reproduce the complete 500 by 400 Director 8 game: screens,
levels, input, frame timing, physics, collision behavior, scoring, animations,
sound, instructions, credits, and links. The stage remains 500 by 400 and is
scaled uniformly by the browser without changing its logical coordinates.

"Faithful" is defined at observable frame boundaries:

- the same input sequence reaches the same game state on the same frame;
- physics positions and velocities agree with the Director reference to the
  precision exposed by Director;
- rendered stage pixels match the reference captures, apart from differences
  explicitly documented and approved;
- the same source samples start, stop, and loop on the same frames;
- text, navigation, scoring, level order, random choices, and external actions
  have the same behavior.

Audio hardware output and physical display scaling are outside the contract.
We can make sample data and event timing identical, but browsers and operating
systems may resample or color-manage their final output differently.

## Why decompilation is necessary but insufficient

ProjectorRays recovered the Lingo and bytecode for all 21 scripts. The `GPS`
behavior contains the complete launch and gravity calculations. For example,
gravity is applied once per frame in planet-list order using a global constant
of `0.9`, followed by the position update.

This gives us formulas and constants, but not every Director runtime semantic.
The source alone does not prove how `point`, `integer`, sprite locations,
`intersects`, event ordering, random numbers, or frame scheduling behave in
Director 8. Expected test results generated by a translation of the same Lingo
would also be circular: the port would effectively be testing itself.

## Independent evidence layers

1. **Preserved program:** hashes identify the canonical DCR and projector.
2. **Recovered implementation:** Lingo and bytecode establish formulas,
   constants, handlers, and update order.
3. **Original runtime oracle:** an isolated Macromedia runtime supplies native
   Lingo execution logs, recorded inputs, per-frame state observations,
   screenshots, and sound events.
4. **Independent modern runtimes:** DirPlayer or LibreShockwave help inspect
   state and diagnose files, but are never treated as the final authority.
5. **Port conformance suite:** the TypeScript implementation replays the same
   scenarios and compares its trace and pixels with checked-in golden data.

## Reference laboratory

The first black-box oracle is the original projector in Windows Sandbox with
networking, clipboard, devices, and host writes disabled except for a dedicated
capture folder. Run `pnpm reference:capture` after Windows Sandbox is enabled.
The command generates the local `.wsb`, launches the isolated projector,
replays the tracked scenario, and records timestamps plus exact 500 by 400
stage images. `pnpm reference:sandbox` only regenerates the `.wsb` file.

On Windows 11 Pro, enable the feature from an Administrator PowerShell and
restart if requested:

```powershell
Enable-WindowsOptionalFeature -FeatureName "Containers-DisposableClientVM" -All -Online
```

The second, higher-resolution oracle is the ProjectorRays-generated DIR opened
in Director 8 inside an isolated VM. It has two complementary non-visual debug
channels:

- Director's native script tracer (`the trace` plus `the traceLogFile`) records
  the exact handler and statement order executed by the original Lingo engine;
- a tiny reference-only observer records frame number, state, `pPoint`, `pVX`,
  `pVY`, planet positions, collisions, and score as structured data without
  replacing their calculation.

Native tracing is enabled only for short diagnostic windows because tracing
every statement slows the vintage runtime. GUI breakpoints are reserved for
one-off investigations: pausing inside a frame changes wall-clock time and can
change mouse state, so values read after an interactive pause are not accepted
as trajectory goldens. The unmodified projector remains the visual cross-check
for the instrumented movie, but screenshots are not used to infer physics.

The authoring laboratory uses the official 30-day Director 8 trial archived
from [NTU's historical software listing](https://www3.ntu.edu.sg/cits2/sw_frames/sw_utilities.html)
through its [2003 Internet Archive capture](https://web.archive.org/web/20030920165749id_/http://www.ntu.edu.sg/cits2/software/download/director8trial.exe).
Its local ignored filename is
`.tools/director8-trial/director8trial.exe`, size 22,855,075 bytes, SHA-256
`9fffc9c721a59a27d5b444aab0f967215f70f51cdbe23ab9c0df845c6efd4d56`.
The executable is never started on the host; it passed the local Windows
Defender scan and is exposed read-only to the disconnected Sandbox. Run
`setup-environment.ps1` from a fresh clone to reproduce all local inputs and
prepare the authoring environment. After setup, run `pnpm reference:authoring`
to start it again after closing any existing Sandbox window. The first setup
run installs Director once and records a narrowly scoped application cache in
the ignored `.tools/director8-cache/` directory.
Subsequent disposable Sandbox sessions restore that cache and open the existing
writable `reference/authoring/spacedpenguin_instrumented.dir` directly, without
running the installer again; the completed cache is mapped read-only. Native
trace logs and structured state traces are written back to the ignored
`reference/authoring/` directory; the original DCR and reconstructed source DIR
remain read-only.

### Black-box baseline established

Scenario `001-level-01-max-stretch-to-ship` is the first reproducible visual
oracle. It boots the canonical projector, enters level 1, drags from logical
point `(413, 303)` to `(469, 355)`, releases after a recorded hold, and samples
the stage at the movie's 30 fps. The original reaches the ship with distance
318 and produces a score of 318. Captures remain outside Git; scenario inputs,
program hashes, and the harness are tracked.

### Authoring debugger baseline established

`pnpm reference:authoring` now performs a non-visual smoke test of the Director
8 authoring oracle. Inside the disconnected Sandbox it:

1. installs the verified Trial build;
2. opens a fresh writable copy of the reconstructed DIR;
3. injects and recompiles the tracked reference observer through Director's
   Message window;
4. proves the observer is callable with the `reference-trace-v1` marker;
5. discovers the IDE's Recompile, Debugger, Toggle Breakpoint, Step, and Run
   menu commands from their native Win32 menu identifiers;
6. runs one second of playback with Director's native Lingo trace enabled.

Baseline `20260829-115105` produced a 48,865-byte, 1,356-line native trace with
153 handler entries, 852 executed-statement entries, and 350 evaluated-value
entries. It records both execution order and Director's own numeric results.
For example, the orbiting behavior records a squared distance of 1,921, clamps
it to 2,500, obtains force `0.0073`, updates velocity to `(-1.7201, -3.8720)`,
and advances to `point(370.6757, 358.1712)`. The ignored trace is identified by
hash in `reference/manifests/authoring-debug-baseline-20260829.json`.

The authoring harness no longer creates screenshots. Images remain part of the
separate black-box pixel-conformance workflow, not the source of physics or
event-order expectations.

## Required characterization scenarios

- minimum, intermediate, and maximum sling stretch at cardinal and diagonal
  angles;
- trajectories with zero, one, and multiple planet influence regions;
- launches that graze, hit, and narrowly miss a planet;
- target intersection at its edges and center;
- leaving and re-entering the 500 by 400 stage and the outer flight rectangle;
- moving/orbiting planets with controlled launch frames;
- bonus collection boundaries;
- crash bounce and timeout behavior;
- scoring for representative distance, level, and attempt counts;
- each menu, instruction, alert, end-game, and high-score transition;
- deterministic random animation sequences from known initial conditions.

Every scenario records its initial state and input in data. Golden outputs are
captured from the reference environment, never calculated by the port.

## Acceptance gates

- **Logic:** exact state, integer, symbol, and event equality per frame, with
  Director handler ordering backed by a native trace or focused
  characterization run.
- **Physics:** exact values when Director exposes them; otherwise a documented
  numeric tolerance tighter than any value capable of changing a rendered
  coordinate or collision outcome.
- **Rendering:** exact 500 by 400 stage captures for stable frames. Static text
  and vector assets may be prerendered where browser rasterization would vary.
- **Audio:** identical decoded source samples and frame-accurate event logs.
- **Completeness:** every original frame label, level, cast member, link, and
  user-visible branch is represented in the inventory and exercised or marked
  unreachable with evidence.
